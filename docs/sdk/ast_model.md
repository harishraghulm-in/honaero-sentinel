# HonAero Sentinel — AST Domain Model Specification

The Sentinel AST subsystem processes C source files and maps them into strongly-typed domain models with exact source locations (`file`, `line`, `column`).

---

## 1. Source Location Integrity

Every extracted construct retains its source coordinates:
```json
{
  "file": "cabin_pressure.c",
  "line": 9,
  "column": 5
}
```

---

## 2. Decision and Condition Model

Decisions represent boolean branching expressions controlling execution flow (e.g., in `if` statements):
- **Decision (`DecisionInfo`)**:
  - `id`: Unique identifier (`D1`, `D2`).
  - `expression`: Full source expression string (`pressure > 900 && altitude < 10000 && sensor_val > 900`).
  - `line_number`: Source code line.
  - `conditions[]`: Atomic sub-expressions.
- **Atomic Condition (`ConditionInfo`)**:
  - `id`: Condition index (`C1`, `C2`, `C3`).
  - `expression`: Sub-expression string (`pressure > 900`).
  - `relational_operator`: Comparison operator (`>`, `<`, `==`, `!=`, `>=`, `<=`).
  - `left_operand`: Variable or expression (`pressure`).
  - `right_operand`: Comparison threshold (`900`).
  - `variable_references[]`: Input variables referenced.

---

## 3. Dependency Detection and Stub Classification

All external function calls encountered inside function bodies are registered as dependencies:
- `REAL`: Linked against production compilation units or environment files.
- `STUB`: Replaced with deterministic mock functions generated by Sentinel.
  - Configurable with successive return arrays (`return_values: [950, 950, 950]`).
  - Records invocation counts and parameter captures.
  - Reset function `sentinel_reset_stubs()` called prior to each test vector execution.
